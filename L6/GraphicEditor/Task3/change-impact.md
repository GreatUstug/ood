# Анализ влияния нового требования (Change Impact)

## 1. Новое требование

Пользователь должен иметь возможность **выделять и удалять отдельные фигуры
внутри вложенных групп**, в том числе несколько фигур на разных уровнях вложенности.
Если после удаления в группе остаётся менее двух фигур, такая группа **автоматически
распадается**. Удаление должно быть **обратимым**: Undo восстанавливает удалённые
фигуры и исходную структуру групп, Redo повторяет удаление.

Реализовывать не требуется — только архитектурный анализ.

## 2. Исходное состояние (as-is)

По C3-диаграмме (`editor-c3`) и коду редактора:

- `Picture` хранит **только верхний уровень**: `unordered_map<string, unique_ptr<Figure>> m_shapes`
  и `vector<string> m_order`. Вложенные фигуры живут внутри `GroupFigure::m_children`.
- `Picture::BuildShapeInfo()` обходит **только `m_order`** → `ShapeListView` и
  `TimelineView` видят только верхний уровень.
- `Picture::HitTest(x, y)` идёт по `m_order` в обратном порядке и вызывает
  `Figure::HitTest`. Для группы `GroupFigure::HitTest` рекурсивно проверяет детей,
  но возвращается **id группы**, а не ребёнка.
- `Picture::DeleteShapes` / `ExtractFigure` работают **только с верхним уровнем**
  (`m_shapes`), но у `Figure` есть `ExtractChild(id)` — задел под вложенные операции.
- `EditorState` хранит `set<string> m_selectedIds`, а `HasValidSelection` /
  `GetValidSelectedIds` фильтруют по `Picture::HasShape(id)` → **вложенные id
  отфильтруются**, даже если бы попали в выделение.
- `DeleteCommand` сохраняет `(index, unique_ptr<Figure>)` для верхнего уровня —
  для вложенных нужен другой механизм восстановления.
- `GroupCommand` / `UngroupCommand` работают **только с верхним уровнем**.
- `SaveService` / `LoadService` **рекурсивны** для групп — формат уже поддерживает
  вложенность, менять IO не нужно.
- `DrawVisitor` **рекурсивен** для групп — отрисовка вложенных работает.
- `DrawSelectionFrame` рисует рамку по `GetBounds()` — для выделения ребёнка нужен
  bounds ребёнка, а не группы.

**Вывод as-is:** модель «умеет» дерево (`GroupFigure`), но **вся остальная система
работает с плоским верхним уровнем**. Это осознанное упрощение текущей версии,
а не баг.

## 4. Сценарий (to-be): от действия до Undo

1. Пользователь кликает по фигуре **внутри группы** (возможно, с Ctrl/Shift для
   нескольких на разных уровнях).
2. `EditorWindowController::HandleEvents` → `EditorController::HandleEvent` →
   `InputRouter::OnMousePressed`.
3. `InputRouter` вызывает **`Picture::HitTestDeep(x, y)`** (новый метод) →
   получает id **самой глубокой** фигуры под курсором.
4. `ShapeTransformController::HandleShapeClick` (или отдельная ветка роутера)
   обновляет `EditorState::SetSelectedIds` — теперь в множестве могут быть
   **вложенные** id. `HasValidSelection` использует `HasShapeDeep`.
5. Пользователь нажимает `Delete` (или кнопку в toolbar).
6. `ShortcutController` (или `InputRouter::HandleToolbarAction`) создаёт
   **`DeleteNestedCommand(picture, selectedIds)`** и вызывает
   `Document::GetHistory().Execute(...)`.
7. `DeleteNestedCommand::Execute`:
    - для каждого id находит **путь** `(parentId, childIndex)` через `FindParent`/`GetPath`;
    - извлекает фигуру (для вложенной — `GroupFigure::ExtractChild`, для верхней —
      `Picture::ExtractFigure`);
    - сохраняет снимок фигуры и её путь;
    - **проверяет группы-родителей**: если после извлечения в группе осталось < 2
      фигур — **распадает** её (извлекает из родителя, детей поднимает на уровень
      родителя с сохранением порядка), и сохраняет **снимок распавшейся группы**
      для Undo;
    - каскадно повторяет проверку для родителя родителя (если группа была вложенной).
8. `Picture::NotifyPictureObservers()` → `ShapeListView`/`TimelineView` обновляют
   `ShapeInfo` (если они теперь умеют показывать вложенность — иначе это отдельный
   риск, см. п.5).
9. `EditorState::ClearSelection()` (или выделение оставшихся).
10. **Undo** (`Ctrl+Z`): `CommandHistory::Undo()` → `DeleteNestedCommand::Unexecute`:
    - восстанавливает **распавшиеся группы** (создаёт `GroupFigure` с сохранёнными
      id/цветом/time/duration, добавляет детей в исходном порядке);
    - восстанавливает **удалённые фигуры** на их пути `(parentId, childIndex)`
      (для верхних — `AddShape(figure, index)`, для вложенных — `AddChild` в нужную
      позицию, для чего у `GroupFigure` нужен `InsertChild(index, child)`);
    - `ShortcutController::ApplySelection(affectedIds)` ставит выделение.
11. **Redo** (`Ctrl+Y`): `DeleteNestedCommand::Execute` повторяет удаление и распад
    (команда хранит всё необходимое состояние — она не «пересчитывает» пути заново).

## 5. Новые взаимодействия / изменения связей

| Связь                                              | Было                                      | Стало                                                                                 |
|----------------------------------------------------|-------------------------------------------|---------------------------------------------------------------------------------------|
| Input Routing → Document Model                     | `HitTest` (возвращает id группы)          | `HitTestDeep` (возвращает id самой глубокой фигуры)                                   |
| Input Routing → Editor State                       | `SetSelectedIds` с верхними id            | `SetSelectedIds` с вложенными id (контракт `HasValidSelection` меняется)              |
| Shortcuts / Input Routing → Command & Undo History | `DeleteCommand` (верхний уровень)         | `DeleteNestedCommand` (вложенные + распад групп)                                      |
| Command & Undo History → Document Model            | `DeleteShapes` / `ExtractFigure`          | `DeleteShapesDeep` / `ExtractFigureDeep` + `InsertChild` (новый)                      |
| Panel Views → Document Model                       | `GetOrder` / `GetShape` (верхний уровень) | опционально `GetTree` / `GetChildren` (если панели показывают вложенность)            |
| Scene View → Editor State                          | `GetSelectedIds` (верхние)                | `GetSelectedIds` (может содержать вложенные) → `DrawSelectionFrame` по bounds ребёнка |

## 6. Архитектурные риски и вопросы (минимум два)

1. **Разрыв между `Picture` (плоский) и `GroupFigure` (дерево).**
   Это **главный риск**. Выделение, удаление, hit-test, панели, `EditorState` —
   всё работает с плоским верхним уровнем. Варианты:
    - **(a)** «Поднять» дерево в `Picture` (хранить `parentId` для каждого id или
      единое дерево) — большие изменения в Model, View, State.
    - **(b)** Ввести **путь** `(parentId, childId)` и оставить `Picture` плоским,
      но добавить `FindParent`/`GetPath`/`HasShapeDeep` — меньше изменений, но
      больше вычислений при каждом hit-test/удалении.
    - **(c)** Гибрид: `Picture` хранит индекс `id → parentId`, обновляемый при
      добавлении/извлечении. Нужно проверить производительность и консистентность
      при Undo/Redo.
      **Вопрос до реализации:** какой вариант выбираем и как он влияет на
      `ShapeInfo`, `ShapeListView`, `TimelineView`?

2. **Авто-распад группы при < 2 фигур — необратимая структурная операция.**
   Для Undo нужно сохранять **снимок группы**: id, цвет, time, duration, список
   детей с порядком. Вопросы:
    - Распад **каскадный**? Если группа внутри группы тоже стала < 2 — распадается ли
      она? (Рекомендация: да, каскадно, иначе останутся «пустые» группы.)
    - Куда поднимаются дети распавшейся группы — на уровень родителя, **с сохранением
      порядка** относительно соседей? (Нужен `InsertChild(index, child)` у `GroupFigure`
      и корректная вставка в `Picture::m_order`.)
    - Что если после удаления группа стала **пустой** (0 детей)? (Распад = удаление
      группы, дети не поднимаются.)

3. **Выделение нескольких фигур на разных уровнях.**
   `EditorState` хранит `set<string>`, но `HasValidSelection` / `GetValidSelectedIds`
   фильтруют по `Picture::HasShape(id)`. Вложенные id **отфильтруются**. Придётся
   менять контракт: либо `HasShapeDeep`, либо `Picture` должен знать о вложенных.
   **Вопрос:** как `ApplySelection` после Undo/Redo восстанавливает выделение
   вложенных фигур?

4. **Дублирование точки создания `DeleteCommand`.**
   Сейчас `Delete` создаётся и в `InputRouter::HandleToolbarAction`, и в
   `ShortcutController`. При добавлении `DeleteNestedCommand` легко забыть одну
   из точек. **Вопрос:** вынести создание в отдельный метод/контроллер?

5. **Панели не показывают вложенность.**
   `ShapeListView`/`TimelineView` работают с плоским `ShapeInfo` (только `id`, `type`).
   Пользователь не сможет выбрать фигуру внутри группы, если её не видно.
   **Вопрос:** расширять `ShapeInfo` (добавить `parentId`, `depth`) и рисовать
   дерево в панелях, или оставить плоский список и давать выбирать только через
   сцену?

6. **`SetTimeCommand::alreadyApplied` и подобные костыли.**
   При новых командах для вложенных операций легко наступить на ту же проблему
   preview→commit. **Вопрос:** придерживаться единого паттерна (preview в
   `EditorState`, commit — команда, команда хранит всё для Undo).

## 7. Разделение as-is / to-be (сводка)

| Аспект          | As-is                       | To-be                                                                     |
|-----------------|-----------------------------|---------------------------------------------------------------------------|
| `Picture`       | плоский верхний уровень     | плоский + `FindParent`/`GetPath`/`HasShapeDeep` (или дерево — по решению) |
| `EditorState`   | фильтрует только верхние id | учитывает вложенные id                                                    |
| `DeleteCommand` | верхний уровень             | `DeleteNestedCommand`: пути + снимки распавшихся групп                    |
| `GroupFigure`   | `ExtractChild`              | + `InsertChild(index, child)` для восстановления порядка                  |
| Hit-test        | возвращает id группы        | `HitTestDeep` — самую глубокую фигуру                                     |
| Панели          | плоский список              | опционально — дерево (или выделение через сцену)                          |
| Рамка выделения | по bounds группы            | по bounds выделенного ребёнка                                             |
| IO              | рекурсивный                 | без изменений                                                             |
| Undo/Redo       | верхний уровень             | вложенные + восстановление структуры групп                                |

## 8. Вывод

Требование **не ломает** архитектуру, но **вскрывает разрыв** между «модель умеет
дерево» и «всё остальное работает с плоским верхним уровнем». Основные изменения
локализованы в **Document Model** (новый API для вложенных), **Command & Undo
History** (новая команда с путями и снимками групп), **Editor State** (контракт
выделения) и **Hit-test** (самая глубокая фигура). Панели и рамка выделения —
следствие. IO и отрисовка менять не нужно.

Главные риски: выбор представления вложенности в `Picture`, каскадность распада,
восстановление порядка детей при Undo и дублирование точки создания команды.
Все они **проверяемы до реализации** и не требуют переписывания архитектуры.
